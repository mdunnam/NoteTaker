## Bug Fixes

### PDF Upload: Buffer → Uint8Array
- **File:** `src/lib/fileParser.ts`
- **Problem:** pdf-parse was receiving a Node.js `Buffer`, which it rejected with `Please provide binary data as Uint8Array`.
- **Fix 1:** Swapped `Buffer.from(buffer)` → `new Uint8Array(buffer)` in both v1 and v2 call paths.
- **Fix 2 (root cause):** pdf-parse v2 pulls in pdfjs-dist, which tries to load `pdf.worker.mjs` — a file that doesn't exist in a Vercel serverless bundle. Downgraded to `pdf-parse@^1.1.1` which is pure Node with no worker dependency.
- **Fix 3:** Added `serverExternalPackages: ["pdf-parse"]` to `next.config.ts` to prevent webpack from bundling the package (belt + suspenders).

## New Features

### File Import Pipeline
- **Route:** `POST /api/import`
- **File:** `src/app/api/import/route.ts`
- Accepts multipart form data with up to 50 files (50 MB each).
- Extracts text server-side via `src/lib/fileParser.ts`.
- Creates one Note per file with `status: PROCESSING` and enqueues AI enrichment.
- Supports: PDF, DOCX, DOC, RTF, XLSX, XLS, CSV, TXT, MD, JSON. PPTX returns a stub message.
- Optional `projectHint` and `contextHint` form fields passed through to enrichment.

### File Parser
- **File:** `src/lib/fileParser.ts`
- Unified server-side text extraction for all supported file types.
- Uses: `pdf-parse@1.1.1` (PDF), `mammoth` (DOCX/DOC/RTF), `xlsx` (XLSX/XLS), native `file.text()` for text formats.
- Truncates content to 12,000 chars per note with a notice if exceeded.
- Stubs unsupported types with a friendly message instead of throwing.

### Daily Digest
- **Route GET:** `GET /api/digest` — fetch today's digest (auto-generates if missing)
- **Route POST:** `POST /api/digest` — force-regenerate today's digest
- **Page:** `/dashboard` — new page, first item in sidebar
- **Files:**
  - `src/lib/dailyDigest.ts` — AI generator, cache layer, fallback builder
  - `src/app/(app)/dashboard/page.tsx` — server component, loads digest SSR
  - `src/app/api/digest/route.ts` — GET + POST handlers
  - `src/components/dashboard/DashboardClient.tsx` — interactive client UI

#### What the digest produces
The AI reads up to 60 recent notes, all entities, extracted tasks, dates, and the user's thinking memory, then outputs a structured briefing with these sections:

| Section key | Label | What it contains |
|---|---|---|
| `open_loops` | Open Loops | People who asked you something; unanswered threads |
| `upcoming` | Upcoming | Events, deadlines, interview prep suggestions |
| `active_projects` | Active Projects | Per-project status + suggested next step |
| `today_sparks` | Today's Sparks | Novel ideas or threads from today's note dump |
| `clarify` | Needs Clarity | Ambiguous notes; direct, sometimes witty questions |
| `wins` | Wins | Anything completed or shipping |

Each item has: headline text, optional expandable detail, urgency (high/medium/low), and links to source notes.

#### Caching
- Generated once per calendar day, stored in `DailyDigest` DB table.
- `GET /api/digest` returns the cached version; `POST /api/digest` regenerates and overwrites.
- UI has a "Refresh" button that calls POST and triggers a router refresh.

#### Database: DailyDigest model
```prisma
model DailyDigest {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  date        String   // "YYYY-MM-DD"
  content     Json     // DigestContent structured briefing
  noteCount   Int      @default(0)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  @@unique([userId, date])
  @@index([userId])
}
```

## Migration Required

Run this SQL in Supabase (or wherever your Postgres lives) before the new build goes live:

```sql
CREATE TABLE "DailyDigest" (
    "id" TEXT NOT NULL,
    "userId" TEXT NOT NULL,
    "date" TEXT NOT NULL,
    "content" JSONB NOT NULL,
    "noteCount" INTEGER NOT NULL DEFAULT 0,
    "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
    "updatedAt" TIMESTAMP(3) NOT NULL,
    CONSTRAINT "DailyDigest_pkey" PRIMARY KEY ("id")
);
CREATE UNIQUE INDEX "DailyDigest_userId_date_key" ON "DailyDigest"("userId", "date");
CREATE INDEX "DailyDigest_userId_idx" ON "DailyDigest"("userId");
ALTER TABLE "DailyDigest" ADD CONSTRAINT "DailyDigest_userId_fkey"
  FOREIGN KEY ("userId") REFERENCES "User"("id") ON DELETE CASCADE ON UPDATE CASCADE;
```
